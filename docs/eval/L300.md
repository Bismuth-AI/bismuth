# L300~L308 — 300건 전량, 여덟 라운드

`docs/eval/README.md` 채점표. 30건에서 잡은 수정 넷 + 문서 유실 수정 + 라우팅 순서 수정이
들어간 뒤의 상태다.

## 셀 수 있는 것

| | L300 | L301 | L303 | L306 | L307 | L308 |
|---|---|---|---|---|---|---|
| 실격선 | 통과 | 실격(잎86) | 통과 | 통과 | 실격(잎53) | 통과 |
| 통과 폴더 | 0 ✓ | 0 ✓ | 0 ✓ | 0 ✓ | 0 ✓ | 0 ✓ |
| 한 층의 갈래 | 7 ✓ | 5 ✓ | 5 ✓ | 5 ✓ | 5 ✓ | 5 ✓ |
| 깊이 (권장 3) | 2 ✓ | 3 ✓ | 4 | 5 | 5 | 3 ✓ |
| 미분해 더미 | 1 | 2 | 2 | 3 | 2 | 1 |
| 가장 큰 잎 (권장 25) | 33 | 86 | 40 | 38 | 53 | 37 |
| 문서 유실 | 0 ✓ | 0 ✓ | 0 ✓ | 0 ✓ | 0 ✓ | 0 ✓ |

L302, L304, L305는 제외한다 — L302는 같은 이름으로 두 프로세스를 겹쳐 띄운 실행 실수,
L304·L305는 축 가드를 완전히 걷어낸 실패한 실험(아래).

**6/6 안정**: 통과 폴더 0, 한 층의 갈래 밴드 안, 문서 유실 0.
**0/6**: 가장 큰 잎 25 이하, 미분해 더미 0.

## 이번에 잡은 것

| 결함 | 로그에서 본 증거 | 결과 |
|---|---|---|
| `<축>: <이름>` 노트 | 표지 거부 5건 전부 225~321자, 전부 "이 폴더의 문서들은…"으로 시작 | 길이 초과 소멸 |
| 부정 정의 폴더 | `비과학기술 분야 소관` — 축을 소관 부처로 잡아 X와 not-X | 소멸 |
| 전부를 덮는 부류 | 표지가 네 주제 나열인데 `emerged=true` | 갈래 중앙값 2→3 |
| **문서 8건 유실** | `.bismuth/boundary-*/`에 갇힘 | **0건, 6/6** |
| 루트 폭 고정 | 루트에서 라우팅 21회 대 emerging 17회, 라우팅이 먼저 | 100건에서 폭 2→5 |

문서 유실은 이 세션에서 만든 회귀였다. 재작성이 모든 문서를 스테이징으로 옮긴 뒤 그룹이
가져간 것만 꺼내는데, 배정에 `STAY`를 허용하면서 "모든 문서는 배정된다"는 보장이 깨졌다.
오류도 실패 기록도 없이 8건이 볼트에서 사라졌다 — 100건을 돌리지 않았으면 몰랐다.

## 되돌린 실험: 조상의 축 재사용

**관측**: 84건 더미가 `법령의 주제`로 `규제자유특구 및 지역특화발전특구`라는 진짜 부류를
제안했고, 루트가 같은 축을 쓴다는 이유로 39번 거부당했다. 폴더 이름이 그 축의 한 *값*일 뿐인데
축이 소진됐다고 판정한 것이다.

**시도 1 — 가드를 완전히 제거**: 실패. 한 라운드는 7층 복도를 만들었고
(`과학기술 및 과학관 → 과학기술 주체 및 지원 → 과학기술 정책 및 운영 → …`, 층마다 0~2건),
다른 라운드는 아무것도 안 나눠 300건이 전부 루트에 남았다. 되돌렸다.

**시도 2 — 좁은 예외**: 재사용은 그것이 만들 이름이 폴더 자기 이름의 **더 좁은 값**일 때만
허용하고, 이름을 폴더 이름과 바꿔도 독자가 차이를 못 느끼면 거부한다. L308이 깊이 3·더미 1로
L306(깊이 5·더미 3)보다 낫고 L307은 실격 — 편차 안이라 아직 확정 못 한다.

## 남은 것과, 그것이 무엇인지

가장 큰 잎과 미분해 더미는 여섯 라운드 내내 목표에 못 미쳤다. 원인을 호출까지 따라가 보면
프롬프트 문제가 아니다.

L308의 37건 잎 `이공계지원 및 과학기술 경쟁력/이공계인력지원`은 **여섯 번밖에 질문받지
않았고**, 그 여섯 번이 제안한 것은 전부 `과학기술거버넌스` 계열이었다. 폴더 이름은 인력지원인데
안에 든 것은 거버넌스 법령이다. 축 심사는 옳게 거부했다 — 거버넌스는 인력지원의 더 좁은 값이
아니다.

**즉 이 폴더가 안 나뉘는 이유는 나눌 축이 없어서가 아니라 이름이 내용을 가리키지 않아서다.**
잎 크기는 그 증상이고, 고칠 자리는 그 폴더가 만들어진 시점 — 부류를 뽑고 구성원을 고르는
단계다. 세분화 프롬프트를 한 번 더 손보는 것으로는 닿지 않는다.
