# 루프 체크리스트

**루프를 돌리기 전과 후에 이 파일을 읽는다.** 절차는 [README.md](README.md)에 있고, 여기는
빠뜨리기 쉬운 것만 짧게. 아래 항목은 전부 실제로 빠뜨린 적이 있는 것들이다.

## 돌리기 전 — 실험 설계를 먼저 적는다

- [ ] **가설 한 문장.** 무엇이 원인이라고 보는가
- [ ] **어떻게 재는가.** 어느 지표, 몇 회. 한 회로는 판정하지 않는다
- [ ] **결과별 다음 행동을 미리 정한다.** 이게 빠지면 결과를 보고 눈앞의 실패를 쫓게 된다
- [ ] **크기는 사다리대로.** 30건(3분) → 100건(7분) → 300건(20분).
      한 단계 3회 연속 깨끗하기 전에는 안 올라간다
- [ ] **큰 데서 찾은 결함은 가장 작은 재현 크기로 내려와서 고친다**
- [ ] 같은 이름으로 두 번 띄우지 않는다 (볼트를 덮어쓴다)

## 돌린 후 — 순서대로, 건너뛰지 않는다

- [ ] **1. 스코어카드** — `python scripts/measure_vault.py ~/bismuth-runs/<이름>`
      어디가 아픈지만 본다. **여기서 순위를 매기지 않는다**
- [ ] **2. 문서 수 확인** — `find <볼트> -name '*.pdf' | wc -l` 이 N과 같은가,
      `<볼트>/.bismuth`에 pdf가 남아 있지 않은가
- [ ] **3. 트리를 읽는다** — 폴더 이름과 그 안의 문서 제목을 직접 대조.
      README 2.2의 스크립트. **이걸 아홉 라운드 연속 건너뛴 적이 있다**
- [ ] **4. 채점표대로 결함을 센다** — [../eval/README.md](../eval/README.md)의 A~E,
      항목별 개수와 실례를 `docs/eval/<라운드>.md`에 기록. 총점으로 뭉치지 않는다
- [ ] **5. 결함마다 그걸 만든 호출을 연다** — SPEC 6.3. 이 단계를 건너뛰면 루프가 무의미하다
      ```
      python scripts/inspect_run.py <로그> --folder "<결함 폴더>"   → # --call <id>
      python scripts/inspect_run.py <로그> --call <id>
      ```
- [ ] **6. 관측한 실패와 바꿀 코드를 일대일로 잇는다.** 커밋 메시지에 실측값을 적는다

## 커밋 전

      (`pytest | tail`은 실패를 삼킨다 — 실패한 채로 커밋한 적이 있다)
- [ ] TEAM.md 소유 규칙대로 레이어별 계정

## 자주 하는 착각

- 스코어카드가 좋다 ≠ 구조가 좋다. `A/B/C`로 나눠도 숫자는 만점이 나온다
- 한 라운드가 좋아졌다 ≠ 수정이 통했다. 같은 코드가 라운드마다 다른 트리를 만든다
- 테스트 통과 ≠ 분류 품질. Fake LLM은 계약만 지킨다
- 어떤 항목이 **0으로 나왔다**는 것은 "좋다"가 아니라 **"이 크기에서는 관측할 수 없다"**
  일 수 있다. 30건에서 A1이 0이었던 것이 그 경우였다
