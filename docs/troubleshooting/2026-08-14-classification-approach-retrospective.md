# 2026-08-14 분류 접근법 회고와 범용성 감사

## 이 문서의 지위

이 문서는 지금까지 시도한 분류 구조와 실제 실행 결과를 보존하는 회고다. 새로운 구현을 승인하는
ADR이 아니다. 다음 피벗은 별도 ADR과 코드 변경으로 진행해야 한다.

품질에 관한 결론은 실제 사용자가 확인한 결과와 raw 로그가 남은 실행만 근거로 한다. Fake LLM
테스트 통과는 계약과 안전성 근거일 뿐 실제 분류 품질 근거가 아니다.

## 변하지 않는 대전제

1. 나무 한 그루가 아니라 장서 전체의 숲을 보고 탐색에 유용한 구조를 만든다.
2. 어떤 문서, 언어, 기관, 업종이 들어올지 미리 알 수 없다.
3. Bismuth는 특정 사용자의 법령 정리기가 아니라 오픈소스 라이브러리다.
4. 한 테스트 말뭉치에서만 작동하는 규칙은 개선이 아니다.
5. 모델은 의미를 판단하고, 호스트 코드는 파일시스템 안전성과 제출 계약을 검증한다.

## 실제로 거친 접근법

### 1. 구조화된 다단계 하네스

호스트가 카드 생성, 기존 폴더 배치, 다문서 후보 생성, 구성원 판정, 의미 검토, 적용 순서를
통제했다. 모델은 단계별로 제한된 질문에 답했다. 사용자가 육안으로 확인한 결과물 품질은 지금까지
시도한 방식 중 이 방식이 가장 좋았다. 단점은 호출 단계가 많고 새로운 실패 유형마다 명시적인 계약과
복구 흐름을 설계해야 한다는 점이었다.

### 2. 결정론적 레이어 강화

독립적인 결정론적 의미 분류기를 완성해 시험한 것은 아니다. 경로 정규화, family 원자성, 누락과
중복, 트랜잭션, rollback, 허용된 handle 검사처럼 모델 결과를 제한하는 코드를 계속 강화했다.

이 과정에서 안전 검증과 의미 휴리스틱의 경계가 흐려졌다. 루트 일반어 목록, 한국어 분기,
법·규제·정책·행정·기관 직제에 관한 표현이 운영 코드와 프롬프트에 들어갔다. 이는 정답 폴더 매핑은
아니지만 현재 한국 법령 말뭉치의 실패를 일반 규칙으로 승격한 도메인 누출이다.

### 3. 전역 window 구조 계획 에이전트

도착 문서를 bounded window로 격리하고 planner가 tree, inventory, sidecar와 관련 증거를 탐색한 뒤
계획을 제출하게 했다. critic과 결정론적 검증기가 shadow plan을 검토했다. 실제 실행에서는 장문
반복, 잘못된 단계의 도구 호출, 권한과 window 불일치, family와 window의 충돌, 결론 단계 정지,
긴 실행시간, 계획 전체 무적용이 반복됐다. 관찰성과 컨텍스트 압축은 개선됐지만 분류 품질의 우위로
이어지지 않았다.

### 4. 문서별 폴더 생성 에이전트

ADR-0029에서 한 문서가 들어올 때마다 에이전트가 탐색하고 폴더를 선택하거나 만들도록 피벗했다.
실제 Qwen 96건 실행에서 첫 문서가 만든 광범위한 `법률` 폴더가 94건을 흡수했다. 한 문서는
재사용 가능한 범주와 말뭉치 전체의 공통 속성을 구분할 대조 증거가 부족하다는 것이 확인됐다.

### 5. 현재 하이브리드

ADR-0030 이후 역할은 다음과 같다.

- 문서별 placement agent: 현재 구조를 탐색하고 기존 폴더 또는 현재 위치를 선택한다.
- 로컬 structured harness: 여러 문서의 대조가 생겼을 때만 구조를 만든다.
- 결정론적 검증기: family, 경로, 구성원, 충돌과 트랜잭션을 검증한다.

이론적 장점은 애매한 배치에서 필요한 폴더 증거를 선택적으로 읽고, 문서별 실패를 격리하며, 미래의
검색 에이전트와 유사한 도구 인터페이스를 검증할 수 있다는 것이다. 그러나 현재까지 이 복잡성이 순수
하네스보다 나은 분류 품질을 만든다는 실증 근거는 없다.

## 마지막 실제 150문서 실행

동일한 SHA-256 seed와 동일한 업로드 순서로 법제처 PDF 150개를 실제 `/api/batches` 경로에
업로드했다. 사용자가 UI에서 드래그 앤 드롭했을 때와 같은 서버 인제스트 경로를 사용했다.

### 비교 실행

- `20260814T122226Z_80c70badb6`: 루트 26, 공정거래 25, 과학기술 38, 금융 50,
  중소기업 11. 동일 topology에서 거절된 family를 다시 물어 결국 거짓 양성이 되는 문제가 있었다.
- `20260814T125315Z_24e138624f`: 같은 topology/family 재심사를 한 번으로 제한하고 최종 대비를
  보수적으로 바꾼 뒤의 실행이다.

두 번째 실행의 실제 PDF 구조는 다음과 같다.

```text
vault root        28
공정거래           18
과학기술           34
금융               44
소비자보호           8
소상공인             6
중소기업            12
합계               150
```

중첩 폴더는 생성되지 않았다. 할부거래 family는 소비자보호, 1인 창조기업은 중소기업에 배치됐고,
기관 직제 family와 산업기술단지 family는 보수적으로 루트에 남았다. 실행은 150/150 성공했고 inbox는
0이었다. 구조 안정성은 개선됐지만 1-depth이고, 금융 44개와 과학기술 34개가 한 폴더에 남아 최종
AI 사서 구조로 충분하지 않다.

두 번째 실행의 raw 로그 집계는 loose route 29회, `NEW_SIBLING` 4회, 기존 표지 선택 25회,
중복 topology/family route 0회였다. `finish_reason=length`와 reasoning content는 없었다. 구조화 호출
중 한 CardUpdate가 세 번 반복 차단됐지만 실패가 격리되어 배치는 완료됐다. CardUpdate delta 크기를
줄인 뒤 해당 raw 요청만 실제 Qwen에 재생했을 때는 유효한 JSON으로 완료됐다. 이 재생은 출력 계약
복구 근거이지 전체 분류 품질 근거가 아니다.

## 범용성 감사

### 지켜진 부분

- 운영 코드에 `금융`, `과학기술`, `중소기업`, `공정거래`를 정답 폴더로 매핑하지 않았다.
- 새 폴더 이름은 실제 카드와 모델 판단에서 나왔다.
- LLM provider 포트, 여러 문서 parser, opaque handle, sidecar, 트랜잭션과 rollback은 특정 법령에
  종속되지 않는다.
- family 구현의 핵심은 파일명과 카드에 관찰되는 identity를 사용하며 특정 법률명 목록을 갖지 않는다.

### 지켜지지 않았거나 입증되지 않은 부분

- `_GENERIC_ROOT_SIGNS`에 한국어와 영어의 산업·경제·정책·규제·법률·행정 계열 단어가 있다.
- Hangul 비율을 검사해 한국어 전용 출력 계약을 적용한다.
- 루트 표지와 placement 프롬프트에 법령·기관 직제 실패에서 나온 의미 규칙이 들어갔다.
- 실모델 품질 검증은 사실상 Qwen3.6-35B와 대한민국 법령 PDF 한 말뭉치에 집중됐다.
- 다른 언어, 계약서, 연구 자료, 개인 문서, 소프트웨어 문서, 혼합 Office 파일과 다른 모델을
  사용한 범용성 검증이 없다.
- 같은 말뭉치의 여러 업로드 순서에 대한 구조 안정성 A/B가 없다.
- 생성된 구조를 실제 검색 에이전트가 탐색해 사용자 질문에 답하는 end-to-end 검색 평가가 없다.

따라서 현재 구현을 범용 AI 사서로 검증됐다고 표현하면 안 된다.

## 현재 결론

현재까지의 실제 결과만 보면 다음 판단이 가장 정직하다.

- 구조 생성 품질은 구조화된 다문서 하네스가 가장 좋았다.
- 전역 및 문서별 agentic organizer는 투입 시간과 복잡성에 비해 품질 우위를 보이지 못했다.
- 현재 하이브리드는 순수 하네스보다 낫다는 증거가 없다.
- 자유 탐색은 구조 생성보다 사용자의 질문을 해결하는 검색 단계에서 더 분명한 장점이 있다.

권장 역할 경계는 다음과 같다.

```text
장서 구조 생성: 범용 다문서 하네스
사용자 질의 검색: 파일시스템 탐색 에이전트
예외 조사: 하네스가 판단 불가일 때만 선택적 에이전트
호스트 코드: 의미 중립적인 안전·원자성·트랜잭션 검증
```

### 제거 대상으로 합의한 결정론적 의미 규칙

- 특정 도메인 일반어 blacklist/whitelist
- 언어별 의미 분류 휴리스틱
- 문자열 포함 관계로 폴더 membership을 결정하는 규칙
- 법령·기관·직제에 특화된 의미 판단

### 반드시 유지할 결정론적 안전 규칙

- 볼트 경계와 경로 안전
- 원본과 sidecar의 동반 이동
- 중복·누락·충돌 검사
- 제출된 handle과 capability 검증
- 문서 family 원자성
- 트랜잭션, journal과 rollback

안전 검증을 버리는 것은 결정론적 의미 분류를 버리는 것과 다르다.

## 다음 구현 전에 필요한 결정

아직 코드는 순수 하네스로 되돌리지 않았다. 다음 작업은 별도 설계 후 진행한다.

1. 현재 하이브리드에서 재사용할 카드, folder card, 로그, transaction 계층을 확정한다.
2. 도메인·언어 특화 의미 규칙을 전수 조사하고 코어에서 제거한다.
3. 과거 하네스의 실제 장점과 실패를 현재 코드 구조에 맞게 재설계한다.
4. 고정 정답 taxonomy 없이 국소 다문서 대비로 2-depth 이상을 성장시키는 계약을 정의한다.
5. 최소한 서로 다른 도메인·언어·파일 형식과 업로드 순서에서 범용성 gate를 만든다.
6. 구조 평가와 별도로 검색 에이전트의 질의 성공률과 도구 비용을 평가한다.
