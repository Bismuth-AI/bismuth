## 4. 알아둘 사실

- **catch-all은 구조로 죽었다.** 프롬프트 문구로 3판 연속 실패했고, 스키마에서 이름 칸을
  하나로 줄이자 mini·mini-minimal·nano 전부에서 안 나왔다. **문구를 더 얹으려는 충동이 들면
  그게 실패한 방법이다.**
- **모델은 mini 기본이 맞다.** `effort=minimal`은 6%만 싸고 파편화가 심해진다. **nano는
  reasoning에 쓰면 안 된다** — 세분화가 아니라 *배치* 단계에서 `학술논문/사회과학연구/2025/…`
  같은 4단계 분류체계를 발명한다(ADR-0008 이전 실패 모드).
- **비용의 88%가 카탈로깅이다.** reasoning을 어떻게 만져도 총액은 24% 이상 안 내려간다.
  줄이려면 카탈로깅을 건드려야 한다.
- **재검토는 33건으로 검증할 수 없다.** `due_for_review`가 2배를 요구하는데, 늦게 나뉠수록
  문턱이 코퍼스 밖으로 밀린다. §5.3을 재려면 같은 코퍼스를 두 번 넣어 60건을 만들어야 한다.
- **인박스 3건은 정상이다.** 스캔 PDF(텍스트 레이어 없음). OCR은 없다.
- **로그 파일 크기를 `Get-ChildItem`으로 판단하지 말 것.** Windows는 열린 핸들의 크기·수정시각을
  디렉토리 엔트리에 늦게 반영한다. 0바이트로 보여서 없는 버그를 한참 쫓았다. `wc -c`나 읽어서 볼 것.

```bash

python -c "import json;[print(r['t'][11:19], r['event']) for r in map(json.loads, open('logs/trace.jsonl',encoding='utf-8')) if r['document_id']=='<id>']"
```

|---|---|

| `subdivide.emerging` | 부류 꺼내기 판단과 그 근거 |

## 6. 남은 문제 — 다음 사람의 일

### 6.1 문서 1건짜리 폴더 (미해결, 결정 대기)

UI 3차에서 **11번의 분할 중 7번이 문서 한 건을 옮겼다.** `AI 디지털교과서` 1건,
`히키코모리` 1건, `RAG` 1건, `프롬프팅` 1건… 그래서 루트 잔류가 20%에서 **40%로 늘었다**
(꺼내는 양이 적어 루트가 안 줄어듦).

**제안된 수정: 1건짜리 추출 거부.** 스펙과 프롬프트가 이미 그 규칙을 말하고 코드만 안 지킨다 —
SPEC §3.4 *"대상이 하나면 구분할 것이 없다"*, 프롬프트 `_SIGNS` *"A sign in front of a single
book is not a sign"*. 기존 가드 둘(독식·부모 이름)과 같은 성격의 퇴화 케이스 방어이지
`50개 넘으면` 같은 코퍼스 튜닝이 아니다.

**단, 한 번 제안했다 "휴리스틱"이라는 지적을 받고 철회한 적이 있다.** 그때 내 근거는 "지저분해
보인다"였고 그건 실제로 휴리스틱이었다. 지금 근거는 다르다(스펙이 이미 말함 + 7/11 실측).
**사용자 결정 대기 중.**

### 6.2 아직 안 정해진 것

- **경계 다시 긋기가 안정적인지** — §5의 장치들은 논증이지 측정이 아니다. 60건 이상 필요.
- **순서 독립성**([SPEC.md §3.5](../SPEC.md)) — 아직 한 번도 안 쟀다. 같은 33건을 순서만
  바꿔 두 판 돌리고(`ralf.py --reverse`), **폴더 이름이 아니라 어떤 문서끼리 같이 묶였는지**로
  비교한다.
- **ADR** — ①과 ⑧·⑩은 ADR-0008을 개정할 만한 판단인데 아직 안 썼다. 실측 근거는 이 문서에 있다.
- **`llm_max_concurrency`는 4 그대로**다. 올리면 더 빨라지지만 레이트리밋 위험이라 안 건드렸다.
